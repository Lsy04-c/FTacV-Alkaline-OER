# 求解器加速可行性报告

日期：2026-08-22
范围：低维 Bonke 分子催化模型（`python/oer_aem/molecular_catalysis.py`）
结论：**可行，端到端 126×（拯救者）/ 64×（本机），精度余量三个数量级。**
状态：**可行性验证，尚未进入生产**——正式启用前的门控见第 7 节。

---

## 1. 起因

低维模型单次正演约 0.53 s（本机）/ 0.86 s（拯救者）。一次 MCMC 是
4000 迭代 × 4 链 = 16000 次正演，四个数据集并发时墙钟约 1–2 小时；实测
25 分钟仍无数据集完成。这个成本让"把 MCMC 跑到 R-hat 真正收敛"变得不现实
——冒烟运行里 R-hat 高达 7–419，正是预算不足的表现。

## 2. 方法

先测量再动手，不靠猜。所有数字都是同一参数点、同一输出网格
（128 点/周期）、同一谐波提取路径下的实测值。

精度判据：H2–H4 包络相对误差，参照对象是 `LSODA rtol=1e-8, atol=1e-11`。
实验数据本身的谐波信噪比为 0.7–5.7（`docs/项目纠错.md` 第 14 条），
即实验噪声在 1e-1 量级；因此 1e-3 以下的数值误差都远在噪声之下。

## 3. 基线剖析

```
交流周期        0.2000 s
RC 时间常数     3.08e-04 s   (Ru*Cdl*A)
刚度比          649
时长            25.6 s = 128 个交流周期

LSODA rtol=1e-6:  0.53 s   nfev=56408 (440 次/周期)   njev=4714
单次 RHS 调用     5.36 us
=> RHS 本身占 0.302 s = 全部墙钟的 57%
```

结论：**瓶颈是 Python 回调，不是算法**。刚度比 649 使得每个交流周期需要
数百次 RHS 求值，而每次都要穿过 Python 解释器。

## 4. 无效的尝试（都实测过）

| 方案 | 加速比 | 说明 |
|---|---:|---|
| LSODA + 解析 Jacobian | **0.90x** | 省下的 RHS 调用被 Python 版 `jac` 自身的开销吃掉 |
| LSODA + jac，去掉 `max_step` | 1.04x | 无实质差别 |
| BDF + 解析 Jacobian | 0.25x | 明显更慢 |
| Radau + 解析 Jacobian | 0.15x | 明显更慢，nfev 173412 |
| 放宽到 `rtol=1e-5` | 1.28x | 有限，且要牺牲精度 |

**在 SciPy 框架内换算法或换容差都没有出路**，因为 `solve_ivp` 不接受
`LowLevelCallable`，RHS 必然走 Python 回调。

## 5. 有效方案：编译的定步长 Crank-Nicolson

`cpp/mc_cn_solver.c`：2 状态、Newton 迭代 + 2×2 解析 Jacobian、定步长 CN，
通过 ctypes 调用——与仓库既有 `cpp/oer_cn_solver.cpp` 的桥接方式一致。

**本机（macOS / clang）**

```

128            0.00177      439x      297x    9.2e-04 1.1e-03 1.8e-03
256            0.00334      232x      157x    2.2e-05 4.0e-05 4.9e-05
512            0.00661      117x       79x    1.3e-05 1.4e-05 2.1e-05
1024           0.01292       60x       41x    3.6e-06 3.8e-06 6.0e-06
```

**拯救者（Debian / gcc 12.2）**

```
LSODA rtol=1e-8 参照 : 1.2406 s
LSODA rtol=1e-6 生产 : 0.8262 s

C-CN 步/周期   wall(s)    vs 参照   vs 生产   H2/H3/H4 相对误差
128            0.00140      888x      592x    9.2e-04 1.1e-03 1.8e-03
256            0.00273      455x      303x    2.2e-05 4.0e-05 4.9e-05
512            0.00550      226x      150x    1.3e-05 1.4e-05 2.1e-05
1024           0.01063      117x       78x    3.6e-06 3.7e-06 6.0e-06
```

两点值得注意：

* **误差随步长单调收敛**，且两台机器的误差值在三位有效数字上一致——
  说明这是真实的离散化误差，不是实现偏差。（原型第一版误差不随步长下降，
  查出是输出网格与参考网格差了一个采样点，属实现错误，已修正。）
* `-ffast-math` 对速度无可测收益（0.00273 vs 0.00269 s），对误差无任何
  影响。**因此生产编译不使用 `-ffast-math`**，保留 IEEE 语义以确保可复现。

## 6. 端到端收益（Amdahl）

目标函数不只有 ODE。实测拆分：

| 阶段 | 本机 | 拯救者 |
|---|---:|---:|
| ODE 求解 | 0.5332 s (99.1%) | 0.8578 s (99.5%) |
| 谐波提取 | 0.0052 s | 0.0040 s |
| HarmPer 损失 | 0.0001 s | 0.0001 s |

替换 ODE 之后：

| | 本机 | 拯救者 |
|---|---:|---:|
| C-CN 256 步/周期 | **64x**（ODE 降为 36%） | **126x**（ODE 降为 40%） |
| C-CN 128 步/周期 | **77x**（ODE 降为 24%） | **157x**（ODE 降为 25%） |

**下一个瓶颈是谐波提取的 FFT**，占加速后总时间的 60% 左右。若还要往上推，
下一步是缓存 FFT 计划或只在拟合窗口内做提取——但当前收益已经足够，暂不做。

## 7. 正式启用前必须做的门控

本报告只证明**单个参数点**上快且准，不足以直接用于生产。参照
`WORK_STATUS.md` §19 对 5 步模型 CN 求解器的做法：

1. **跨参数空间等价性门**——在参数边界内抽样（建议 24 个样本），逐样本比较
   总电流、DC、H2–H4 幅值与相位、峰位，阈值预先冻结，失败不调阈值；
2. **逐数据集步长收敛研究**——四组数据的扫速与频率不同，步长需求可能不同，
   不能用 FT8 的结论套到 FT4（1 Hz、扫速 3.9 mV/s）；
3. **稳态初值必须与 LSODA 完全一致**——§19 的教训是初值不一致造成的偏差
   （18.5% NRMSE）远大于积分格式本身的差异；
4. **保留 LSODA 复算**——CN 只用于搜索加速，入选的最优参数必须由 LSODA
   重新计算后才写入结论；
5. 动态库的编译器、版本与编译选项写进 `run_manifest.json`。

## 8. 这件事真正解锁的

不是"省几个小时"，而是**让统计上正确的推断变得可负担**：

| | 现在 | C-CN 之后 |
|---|---|---|
| 单数据集 MCMC（4000×4 链） | 拯救者约 57 min | 约 27 s |
| 四数据集并发全轮 | 1–2 h | 数分钟 |
| 40000 迭代（为 R-hat 收敛） | 不现实 | 约 5 min/数据集 |
| Ru 敏感性、profile likelihood | 只能抽样做 | 可作为常规输出 |

冒烟运行中 R-hat 达 7–419，说明当前预算下的后验不可信。加速之后，
把迭代数提高一个数量级、并对每个参数做 profile likelihood，都在成本之内
——这正是低维主线要回答"哪些参数真正可辨识"所需要的。
