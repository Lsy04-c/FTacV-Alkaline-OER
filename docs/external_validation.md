# 外部校验记录

本项目自建了正演模型、谐波提取、目标函数与 MCMC 采样器。它们有 122 项
**自洽**测试，但自洽测试无法发现"整套实现一致地错"这类问题。本文件记录
用**外部参照**做的独立校验。

背景：2026-08-22 复查文献时发现，本项目引用的每篇方法学论文都使用现成
软件栈（`docs/项目纠错.md` §24），而项目从未做过工具调研。外部校验是
对这一缺口的补救。

---

## 1. MCMC 采样器 vs PINTS（2026-08-22，通过）

**参照物**：PINTS 0.6.1 的 `HaarioACMC`。PINTS 是 Gundry 2021
（ChemElectroChem 8, 2238）与 Dale-Evans 2021（Front. Chem.）使用的推断库，
其 `HaarioACMC` 与 `python/oer_aem/mcmc.py` 实现的是同一算法。

**方法**：同一个解析已知的二维相关高斯后验（ρ=0.8），两个实现各跑
4 链 × 24000 迭代，比较恢复的均值、标准差、相关系数。
脚本：`scripts/crosscheck_sampler_vs_pints.py`

| | mean | std | corr | R-hat |
|---|---|---|---|---|
| 真值 | (+1.0000, −2.0000) | (0.5000, 0.8000) | +0.8000 | — |
| 本项目 `mcmc.py` | (+1.0027, −1.9975) | (0.4962, 0.8010) | +0.8015 | 1.0008 |
| PINTS `HaarioACMC` | (+0.9920, −2.0128) | (0.4987, 0.8002) | +0.7969 | 1.0002 |

实现间差异：`|Δmean| = (0.011, 0.015)`、`|Δstd| = (0.0025, 0.0008)`、
`|Δcorr| = 0.005`——均在该样本量的蒙特卡洛噪声内。

**结论**：手写采样器**无系统偏差**，可用于生产。

**这条校验的边界**：它只验证了**采样器**。目标函数、谐波提取、正演模型
都不在其覆盖范围内——采样器再正确，喂给它一个错的似然仍然得到错的后验。

**PINTS 不进入项目依赖**，仅作一次性校验工具，装在隔离环境。拯救者的正式
计算环境依赖保持不变。

## 2. 正演模型 vs 解析极限（2026-08-22，通过）

**参照物**：闭式解，不依赖任何外部软件。
脚本：`python/tests/test_analytic_limits.py`

### 2.1 可逆极限 vs Nernst 闭式解

`k0 = 1e7 s^-1`（可逆）、`kf = 0`（无催化）、`Ru = 0.01 Ω` 时，覆盖度严格
服从 Nernst，法拉第电流有闭式解：

```
theta_ox(t) = 1 / (1 + exp(-f (E_app - E0)))
i_F(t)      = A * gamma * F * f * theta (1-theta) * dE_app/dt
```

**比较前必须扣除同一体系 `gamma = 0` 的电容基线**，并把求解器容差收紧到
`rtol = 1e-9`。满足这两点后：

| 通道 | 相对误差 |
|---|---|
| H2 | 1.4e-05 |
| H3 | 5.5e-05 |
| H4 | 1.6e-05 |

**更正（2026-08-23）**：本节最初报告的是 H1 0.04% / H2 0.13% / H3 0.95% /
H4 0.63%，并把它当作"模型与解析解的一致性"。那些数字里混了两项与模型
无关的误差，实际的法拉第一致性要好两个数量级：

1. **电容污染**。闭式解假设 `Ru -> 0`，而 ODE 用有限 `Ru`，两者电容支路
   存在固定的绝对差异。不扣基线时该差异被较小的法拉第信号除大，表现为
   H3 约 0.65%，且**随 gamma 减小而增大（∝1/gamma）**——正是这个反常
   标度暴露了它不是模型误差。（曾误判为"法拉第反馈 (γF/Cdl)·r_et"，
   但那应随 gamma 下降，实测相反，假设被否定。）
2. **积分误差**。`k0 = 1e7` 的可逆极限极其刚性，默认 `rtol = 1e-6` 下
   差分残差仍有 1e-3–9e-3。

该污染还依赖求解器版本：松容差下 SciPy 1.16.3（拯救者）与 1.18.0（本机）
表现不同，这正是本测试一度在拯救者失败而在本机通过的原因。扣除基线并
收紧容差后，两平台一致。

为此 `molecular_catalysis.simulate()` 增加了可覆盖的 `rtol` / `atol`——
解析校验必须在数值先收敛的条件下做，否则测到的是积分误差而非模型正确性。

### 2.2 催化步 vs 稳态闭式解

`dtheta/dt -> 0` 时 `theta_ox = k_fwd / (k_fwd + k_rev + kf)`，
`i = A * gamma * F * kf * theta_ox`。强催化 + 慢扫下直流电流匹配到 2% 以内。
这一支覆盖 2.1 未覆盖的催化步。

### 2.3 零法拉第极限

远负于 `E0` 时总电流退化为纯电容，偏差 < 0.1%。

**结论**：正演模型的**法拉第核心与催化步**均通过闭式解校验，
法拉第一致性达 1e-5 量级。

**这条校验的边界**：它在 `Ru -> 0`、可逆或强催化的**极限**下验证。
中间区域（准可逆 + 中等 `Ru` 的 RC 耦合）没有闭式解，仍无外部参照。

### 2.4 为什么最终没有用 MECSim

原计划用 MECSim 做数值对照，实际执行时判定不合适：

| 事实 | 来源 |
|---|---|
| 二进制编译于 2019，仓库 `garethkennedy/MECSim_Analytics` 最后更新 2019-05-15 | GitHub API |
| 仓库**未声明许可**；自述写明"MECSim source code itself is not available" | 同上 |
| 依赖 `libgfortran.so.3`（GCC 4.8/5 时代），Debian Bookworm 已不提供 | 拯救者 `ldd` |
| 官网下载页现只提供 2019 年的 Docker 镜像；两台机器均无任何容器运行时 | 实测 |

要跑通它需要额外装配一个 Debian 已下架的运行时。**参照物的可信度会低于
被验证对象**，这与"外部校验"的目的相悖。libgfortran 的 ABI 在大版本间
不兼容，用软链接替代会让数值程序静默给出错误结果，绝不可行。

已完成的只读检查（结论仍有效，可供日后参考）：

```
sha256   6333761c7b127c7d18425002a7e6630fb2991875376c0017c5a434cca9fc630c
type     ELF 64-bit x86-64, dynamically linked, GNU/Linux 2.6.24
符号     只有 gfortran 运行时（字符串、文件 I/O、幂运算）
文件     只读 Master.inp，只写 MECSimOutput.txt
网络/进程 fork / system / execve / socket / getaddrinfo —— 全部不存在
```

顺带第一手证实 **MECSim 是 Fortran 编译产物，不是 MATLAB**（二进制内全是
`_gfortran_*` 符号），与 `docs/项目纠错.md` §24 的澄清一致。

MECSim 的模板包（`Templates.zip` / `TemplateReactions.pdf`，纯文本与 PDF）
仍有参考价值：其 **Mechanism 6（Surface confined catalytic，`Master_SCCat.inp`）**
与本项目低维模型结构一致，可用于核对参数含义与单位约定。

## 3. 目标函数 vs BIOMEC（未计划）

BIOMEC（github.com/lukegun/BIOMEC，GPL-3.0）是 Gundry 2021 的官方实现，
包含本项目按论文文字复现的 `HarmPer` 与 `MLE-ExpHarmPer`。

官方安装路径需 `sudo singularity build`，而拯救者无免密 sudo 且未安装任何
容器运行时——受阻。若第 2 节完成且目标函数需要独立校验，再评估非容器路径。
