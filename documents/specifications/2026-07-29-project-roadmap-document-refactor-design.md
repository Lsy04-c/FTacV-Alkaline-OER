# 项目总览与交接文档重构设计

## 1. 目标

把 `documents/project/PROJECT_SUMMARY.md` 重构为项目唯一总入口。用户或新
Agent 只读这一份文档，就应能回答：

1. 项目解决什么科学问题；
2. 代码由哪些模块组成，数据如何流动；
3. 关键接口、脚本和结果位于哪里；
4. 哪些能力和 Gate 已完成；
5. 当前科学结论和参数角色是什么；
6. 哪些目标尚未完成；
7. 休假期间和恢复实验后分别做什么；
8. 接手项目时如何验证环境、代码和证据。

旧计划可以删除。过程可见性由压缩后的总览、`WORK_STATUS.md`、正式
`acceptance.md` 和 Git 历史共同承担。

## 2. 采用的信息架构

### 2.1 唯一总入口

`PROJECT_SUMMARY.md` 按以下顺序组织：

1. **项目一句话状态**
2. **项目目标与科学边界**
3. **系统架构与数据流**
4. **代码目录与关键接口**
5. **Gate A1–A7 完成状态**
6. **数据、特征和参数当前口径**
7. **已完成功能与正式证据**
8. **未完成目标和阻断条件**
9. **休假期间路线**
10. **恢复实验后的路线**
11. **运行、测试和远程计算入口**
12. **后续 Agent 最小交接步骤**
13. **项目完成定义**

目标长度约 300–450 行。允许包含必要的接口表和证据索引，不复制长篇执行
日志。

### 2.2 历史过程

`WORK_STATUS.md` 保留为完整时间线，不再承担未来计划。文件顶部增加醒目
说明，要求先读 `PROJECT_SUMMARY.md`；今后只追加已经发生的事实。

### 2.3 当前行动计划

`documents/plans/` 最终只保留一份当前计划：

```text
2026-07-29-vacation-and-post-experiment-roadmap.md
```

该计划使用可勾选任务、输入、输出、验收门和停止条件，不能重复项目背景和
历史过程。

## 3. 总览必须保存的内容

### 3.1 项目架构

用一张简短数据流和一张目录/模块表说明：

```text
实验三列数据
→ 严格数据契约
→ DC/复数谐波/电位分辨锁相
→ AEM 正演模型
→ 冻结特征契约
→ 敏感性/profile/合成恢复
→ 条件分析或正式反演
→ 证据归档与 Web 展示
```

目录表至少覆盖：

- `code/python/src/oer_aem/`；
- `code/python/scripts/`；
- `code/cpp/`；
- `config/`；
- `data/raw/`；
- `results/formal/`；
- `documents/`。

### 3.2 关键接口

以表格记录每个接口的职责、输入、输出、当前状态和主要调用方。至少包含：

- 严格实验数据读取与采样诊断；
- M0 物理 RHS 和正演求解；
- LSODA/BDF 正式后端；
- C++ CN 实验后端及其限制；
- 全局复数谐波与 lock-in 特征；
- `InversionObjective` 和冻结通道契约；
- 敏感性、profile、recovery gate；
- Gate A1/A2/A5/A6 validator；
- `oer-wf` 的 prepare/smoke/run/status/sync/verify；
- Web API 和前端入口。

不得把“代码存在”写成“科学通过”。每项使用“实现、验证、正式 Gate”三个
层级之一。

### 3.3 已完成内容

按 Gate 汇总，不按日期复制过程：

- A1：结构和采样通过，元数据待补；
- A2-R：守恒和极端求解路径通过；
- A3：CN 等价性失败，LSODA 保留为正式后端；
- A4：真实谐波稳定性通过；
- A5：通道、权重和特征网格冻结；
- A6：恢复失败关闭，无自由参数；
- A7：远程计算和证据工作流通过。

每个 Gate 链接唯一正式 `acceptance.md`，并写清结论边界。

### 3.4 参数和数据口径

明确保存：

- 四组 FTacV 不是重复实验；
- 列序为电位、电流、时间；
- 当前单位声明为 `V vs RHE`、`A`、`s`；
- 仪器预处理仍缺少一手记录；
- `fixed`、`diagnostic_only`、`free` 参数清单；
- 已确认的强耦合参数对；
- 当前禁止报告可信参数点估计。

### 3.5 未完成目标

未完成项必须按依赖排序：

1. 用户声明元数据补录；
2. 四组数据的条件模型可达性；
3. DC/H1–H3 残差归因；
4. 解除参数耦合的实验设计；
5. 恢复实验后的完整元数据和独立测量；
6. A6-v2 合成恢复；
7. 真实数据正式联合反演；
8. 不确定度和机理结论；
9. 最终 Web 交付。

## 4. 两阶段路线

### 4.1 休假期间

- 补录已知元数据，但保持 Gate A1 `FAIL_METADATA`；
- 使用现有四组数据做条件分析，不作为重复实验平均；
- 判断实验特征是否位于 M0 模型可达范围；
- 分解 DC、H1、H2、H3 的幅值和相位残差；
- 形成多频率、多振幅、多扫描速率实验方案；
- 不重新开放正式 TPE，不报告原始参数点估计。

### 4.2 恢复实验后

- 保存原始仪器方法、RHE 换算和全部预处理记录；
- 独立约束 `Ru`、`Cdl`、面积、负载量和有效位点量；
- 采集结构化 FTacV 条件矩阵；
- 重建敏感性和 profile；
- 建立新的 A6-v2，先过合成恢复再接触真实反演；
- 最后执行不确定度、跨条件验证和机理结论分级。

## 5. 删除规则

可以删除下列 Markdown：

- 已完成实施且已有正式结果、测试和 Git 提交的实施计划；
- 已被后续设计替代的旧路线；
- 与 `PROJECT_SUMMARY.md`、`WORK_STATUS.md` 或正式验收重复的总结；
- 只服务于一次 Agent 交接、且任务已经完成的项目内交接文档。

必须保留：

- 重构后的 `PROJECT_SUMMARY.md`；
- `WORK_STATUS.md`；
- `PROJECT_WORKFLOW.md`；
- 项目纠错文档；
- 当前两阶段计划；
- 仍定义有效接口或治理规则的规范；
- 正式结果目录中的 `acceptance.md`；
- 环境私有文档，但不得提交其新增内容。

删除前用全文搜索检查引用。删除后必须更新根 README、文档 README 和所有
保留文档中的链接。Git 历史承担旧文件恢复能力。

## 6. 后续 Agent 最小阅读集

默认只读：

1. 根 `README.md`；
2. `documents/project/PROJECT_SUMMARY.md`；
3. 当前两阶段计划；
4. 当前任务相关的正式 `acceptance.md`；
5. 需要远程操作时再读 `/Users/liushiyu/gpt/本机环境配置.md`。

不默认读取整个 `WORK_STATUS.md`、旧 Git 历史或全部正式结果。

## 7. 验证

- 总览中的 Gate 状态与正式验收逐项一致；
- 关键接口路径真实存在；
- 所有保留 Markdown 链接有效；
- 当前计划不包含已禁止的正式真实数据 TPE；
- 删除文件均能从 Git 历史恢复；
- `WORK_STATUS.md` 的历史顺序不被改写；
- 仓库布局审计和 `git diff --check` 通过；
- Git 提交只包含项目文档。

## 8. 压力测试

- **过度删除导致接口信息丢失：** 删除前先把有效接口和结论写入总览，再
  执行引用审计。
- **总览再次变成流水账：** 已发生的细节只追加到 `WORK_STATUS.md`。
- **科学状态被简化错误：** 分开记录工程、结构、数值和科学 Gate。
- **旧计划继续误导：** 已关闭路线不保留在当前计划目录。
- **休假期越过证据边界：** 现有四组数据只支持条件分析。
- **恢复实验后直接反演：** 新数据仍须先通过元数据和合成恢复门。

## 9. 非目标

- 不修改代码、原始数据或正式结果；
- 不启动新计算；
- 不改变 A1、A3、A6 的失败结论；
- 不把强相关解释为数学结构不可识别；
- 不在本次重构中确定新实验的具体数值配置。
