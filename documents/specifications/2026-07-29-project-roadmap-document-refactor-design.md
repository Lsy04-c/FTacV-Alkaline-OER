# 项目路线与交接文档重构设计

## 1. 目标

重构项目计划文档，使用户和后续 Agent 能快速回答四个问题：

1. 项目最终要解决什么问题；
2. 当前哪些结论已经由正式证据支持；
3. 当前为什么不能进入正式真实数据反演；
4. 休假期间和恢复实验后分别应做什么。

重构必须保留历史过程和失败证据，不修改代码、数据、正式归档或既有科学
结论。

## 2. 当前问题

- `PROJECT_SUMMARY.md` 同时保存历史路线、当前状态和未来任务，内容过长；
- `WORK_STATUS.md` 是完整流水账，但缺少清晰的当前入口；
- `documents/plans/` 混合已完成、已终止和仍有效的计划；
- 部分旧计划仍描述继续 TPE 或参数恢复，与 Gate A6 的正式
  `FAIL_RECOVERY` 冲突；
- 后续 Agent 需要读取多个长文件才能判断下一步，增加交接成本和误操作风险。

## 3. 方案比较

### 方案 A：只新增一份路线文档

改动最小，但旧入口和新入口会并存，无法消除状态冲突。

### 方案 B：当前入口与历史归档分离

重写当前摘要，建立两阶段主计划，将已完成或终止的实施计划移入归档。
过程仍可追溯，当前入口保持简短。

### 方案 C：删除旧计划

目录最简洁，但会丢失决策过程、失败分支和实施依据，不满足可见性要求。

采用方案 B。

## 4. 文档职责

### 4.1 `documents/project/PROJECT_SUMMARY.md`

作为唯一项目入口，只保存当前有效信息：

- 项目目标和科学边界；
- Gate A1–A7 当前状态；
- 当前三个阻断项；
- 休假期间主线；
- 恢复实验后的主线；
- 当前允许和禁止的行动；
- 关键证据入口；
- 项目完成标准。

目标长度不超过约 300 行。历史执行细节只链接，不复制。

### 4.2 `documents/project/WORK_STATUS.md`

作为按时间追加的历史流水账，不重写旧记录。文件开头增加“当前状态入口”，
指向 `PROJECT_SUMMARY.md` 和当前主计划。今后只追加已执行事实，不在这里
维护未来路线。

### 4.3 当前主计划

新增一份两阶段主计划，放在 `documents/plans/`：

```text
2026-07-29-vacation-and-post-experiment-roadmap.md
```

它只描述尚未执行的工作、依赖、验收门和停止条件。

### 4.4 历史计划

已完成、已失败关闭或被后续 Gate 取代的计划移动到：

```text
documents/archive/plans/
```

移动使用 Git 重命名，保留文件内容和历史。旧计划顶部不批量改写，目录
README 统一说明它们不再是当前执行依据。

### 4.5 索引

更新：

- `documents/README.md`；
- 必要时更新根 `README.md`；
- 新增 `documents/archive/README.md`。

索引明确区分：

- 当前状态；
- 当前计划；
- 历史过程；
- 正式结果；
- 纠错记录。

## 5. 两阶段科学路线

### 5.1 休假期间

不依赖新增实验：

1. 补录已经确认的列序、单位和 RHE 标尺，Gate A1 保持
   `FAIL_METADATA`；
2. 使用四组数据进行条件模型可达性分析，不报告参数点估计；
3. 分解 DC、H1–H3 幅值和相位残差，判断模型不足与参数补偿；
4. 设计用于解除参数耦合的实验矩阵；
5. 只在有明确后续计算需求时优化求解性能。

四组数据不能作为重复实验平均。所有真实数据结论必须标记为条件性或探索性。

### 5.2 恢复实验后

1. 保存完整仪器方法、RHE 换算和预处理记录；
2. 独立测量或约束 `Ru`、`Cdl`、电极面积、负载量和有效位点量；
3. 采集多频率、多振幅、多扫描速率的结构化 FTacV 数据；
4. 用新条件重建敏感性和 profile；
5. 建立 A6-v2 合成恢复门；
6. 只有通过恢复门的参数才进入真实数据联合反演；
7. 最后执行不确定度和机理结论验证。

## 6. 当前科学状态

重构不得改变以下结论：

- A1：`FAIL_METADATA`，四组数据可用于条件分析；
- A2-R：`PASS`；
- A3：CN 正式等价性 `FAIL`，正式结论使用 LSODA；
- A4：真实数据谐波稳定性 `PASS`；
- A5：特征通道契约 `PASS`；
- A6：`FAIL_RECOVERY`，当前自由参数为空；
- A7：计算工作流工程验收 `PASS`。

关闭 validator 的 `PASS` 不得覆盖科学 Gate 的 `FAIL`。

## 7. 交接最小阅读集

后续 Agent 默认只读取：

1. 根 `README.md`；
2. `documents/project/PROJECT_SUMMARY.md`；
3. 当前两阶段主计划；
4. 与当前任务直接相关的正式 `acceptance.md`；
5. 需要远程环境时再读取 `/Users/liushiyu/gpt/本机环境配置.md`。

不得默认读取整个 `WORK_STATUS.md` 或全部历史计划。

## 8. 验证

- Markdown 链接审计通过；
- 所有被移动文件可从归档索引找到；
- 当前摘要中的 Gate 状态与正式 `acceptance.md` 一致；
- 当前计划不包含已经禁止的正式真实数据 TPE；
- 搜索当前入口，不出现“eligible parameters 非空”等过期表述；
- `git diff --check` 通过；
- 只提交项目文档，不提交环境配置或私有交接材料。

## 9. 压力测试

- **归档被误解为删除：** 使用 Git 重命名并提供索引，不删除历史。
- **摘要再次膨胀：** 时间线只写入 `WORK_STATUS.md`，摘要只保存当前状态。
- **计划与状态重复：** 摘要回答“现在是什么”，主计划回答“接下来做什么”。
- **休假期间越过证据边界：** 四组数据只做条件分析，不报告正式参数点估计。
- **恢复实验后直接反演：** 新数据必须先通过元数据、敏感性和合成恢复门。
- **链接因移动失效：** 移动后运行仓库 Markdown 链接审计并修复全部引用。

## 10. 非目标

- 不重写正式结果归档；
- 不删除历史失败记录；
- 不修改代码或计算配置；
- 不启动计算；
- 不重新解释 Gate A6 为结构不可识别；
- 不在本次文档重构中设计具体实验参数数值。
