# OER-FTAcV 可复用计算工作流（oer-wf）项目框架

> 版本：0.3（SSH 基建落地 + 进度更新）
> 最后更新：2026-07-27
> 目标：把稳定、重复、可验证的工程步骤从人工/Agent 对话中剥离，形成可复现、可审计、可恢复的计算工作流平台。
> 核心原则：**工程步骤可复用，科学判断不自动化**。

---

## 1. 项目定位与边界

### 1.1 要解决的问题
- Mac → Windows → WSL 三层 SSH 引号地狱
- commit 专属 worktree 混用与配置漂移
- smoke 与正式计算配置不一致
- systemd 任务状态误判（进程消失 ≠ 成功）
- 结果同步、哈希、provenance 不完整
- Agent 大量额度消耗在重复工程操作上

### 1.2 明确不做的事
- 不自动修改物理模型或科学阈值
- 不自动宣布 Scientific FAIL / PASS 的最终结论
- 不替代科研决策、异常解释与路线选择
- 不引入大型工作流引擎（Airflow / Prefect / Dagster 等）

### 1.3 成功标准
- 一次正式计算从“准备 → 验收 → 归档”的人工/Agent 轮次显著下降
- 任何正式结果都具备完整 provenance（commit + 环境 + 配置 + 哈希）
- 基础设施失败与科学失败严格分离
- 失败后可安全恢复，历史证据永不被覆盖

## 2. 总体架构

```

Mac (开发/验收/归档)
    │
    │  ssh / rsync  (直达 WSL)
    ▼
拯救者 Windows + OpenSSH (Match 规则强制进 WSL)
    │
    ▼
WSL (实际计算环境)
    ├── 主仓库 (含 .venv)
    ├── Git worktree (commit 专属，仅源码)
    ├── systemd 正式任务
    ├── STATUS.json
    └── 结果目录

```

**核心交互模型**：
```

Agent / 用户
    │
    ▼
wf <command></command> [args]          ← 统一 Python CLI
    │
    ▼
结构化 JSON 响应
{
  "status": "pass|fail|warning|running",
  "fail_type": "...",
  "checks": [...],
  "data": {...},
  "next_action": "..."
}

```

Agent 只解析 JSON，根据 `status` 和 `next_action` 推进，不再解析人类日志。

## 4. 核心数据契约

### 4.1 task_spec.yaml（任务声明）

**强制规则**：

- 所有路径均为**相对于 worktree root 的相对路径**（venv 例外，见下方）。
- **禁止**出现 `/Users/...`、`/home/...` 等绝对路径。
- **不再手写 task_id**，只写 `task_name`。运行时自动推导：
  ```
  task_id = f"{commit_short}/{task_name}"
  ```

```yaml
task_name: "solver_equiv_01"          # 唯一任务名
commit: "3f9aad1..."                  # 完整或短 SHA（运行时统一取短 SHA）
description: "求解器等价性验证"

# Python 解释器来源（关键修复）
python:
  source: "main_repo"                 # "main_repo" | "worktree"
  path: ".venv/bin/python"            # 相对对应 root 的路径
  # 运行时解析：
  #   main_repo  → <主仓库绝对路径>/.venv/bin/python
  #   worktree   → <worktree绝对路径>/.venv/bin/python

# 工作树
worktree_root: "worktrees"            # 相对主仓库的前缀

env:
  OMP_NUM_THREADS: "1"
  OPENBLAS_NUM_THREADS: "1"

# 构建（可选）
build:
  required: false
  source: "code/cpp"
  command: "cmake --build code/cpp/build --config Release"
  expected_artifact: "liboercn"       # 平台无关 basename（修复）
  # 运行时根据平台自动追加 .so / .dylib / .dll

# 运行
script: "scripts/run_solver_equiv.py"
args:                                 # 用户自定义参数
  - "--config"
  - "configs/solver_equiv.yaml"
workers: 4
output_dir: "results/solver_equiv_01" # 相对路径基准（修复）

# Smoke 派生
smoke:
  enabled: true
  overrides:
    n_samples: 2
    max_steps: 50
  expected_files:
    - "summary.csv"
    - "manifest.json"

# 正式验收
expected_files:
  - "summary.csv"
  - "manifest.json"
  - "STATUS.json"
validators:
  - schema_check
  - finite_check
  - provenance
  - manifest_hash
```

### 4.2 命令行最终拼装规则（修复）

`wf run` 实际执行的命令为：

```bash
<resolved_python> <script> <args...> --output <timestamped_dir> --workers <n>
```

- `args` 原样追加。
- `--output` 与 `--workers` **始终由 wf 注入并放在末尾**。
- 若 `args` 中已包含 `--output` 或 `--workers`，**立即报错拒绝**，防止冲突。

### 4.3 output_dir 时间戳规则（修复）

| 场景               | 实际创建的目录                                                                      |
| ------------------ | ----------------------------------------------------------------------------------- |
| 普通`wf run`     | `<output_dir>/<YYYYMMDD_HHMMSS>/`                                                 |
| `wf run --force` | 生成**新的**时间戳目录，旧目录完整保留                                        |
| smoke              | `<output_dir>/_smoke_<YYYYMMDD_HHMMSS>/`（或固定 `_smoke_` 子目录，由实现决定） |

时间戳格式统一为 UTC `YYYYMMDD_HHMMSS`。

### 4.4 Mac 本地归档路径（修复）

在 `oer_wf/config.py` 中定义：

```python
MAC_ARCHIVE_ROOT = Path.home() / "OER-FTAcV-archive"   # 可配置
```

最终归档结构：

```text
<MAC_ARCHIVE_ROOT>/
└── results/
    └── <commit_short>/
        └── <task_name>/
            └── <YYYYMMDD_HHMMSS>/
                ├── summary.csv
                ├── manifest.json
                ├── STATUS.json
                └── ...
```

- `wf sync` 把 WSL 侧时间戳目录同步到上述路径。
- `wf verify` 默认查找该 task 下**最新时间戳**目录；也可显式指定时间戳。

### 4.5 STATUS.json（计算脚本强制输出）

```json
{
  "status": "SUCCESS | FAIL_NUMERICAL | FAIL_INFRA",
  "exit_code": 0,
  "timestamp": "2026-07-27T08:00:00Z",
  "error_msg": null,
  "extra": {}
}
```

由计算脚本通过 `try...finally` 或 `atexit` 保证写入。

### 4.6 .wf_lock

```json
{
  "task_id": "3f9aad1/solver_equiv_01",
  "task_name": "solver_equiv_01",
  "spec_hash": "sha256:...",
  "commit": "3f9aad1...",
  "created_at": "2026-07-27T07:55:00Z",
  "worktree_path": "/home/lsy/..."
}
```

### 4.7 统一 CLI 响应

```json
{
  "status": "pass | fail | warning | running",
  "fail_type": "environment | transport | structure | numerical | scientific | null",
  "checks": [
    {"name": "ssh_wsl", "passed": true, "detail": "connected, kernel 5.15"}
  ],
  "data": {},
  "next_action": "wf prepare examples/solver_equiv_01.yaml",
  "message": "人类可读摘要（可选）"
}
```

## 5. 命令清单与状态机

| 命令                                              | 职责                                                   | 关键规则                                   |
| ------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------ |
| `wf doctor`                                     | 只读环境检查（SSH、时钟、Git、Python、rsync、systemd） | 时钟差 > 5s → warning                     |
| `wf prepare <spec>`                             | 创建/复用 commit 专属 worktree，写入`.wf_lock`       | spec_hash 不匹配 → 报错，要求 clean       |
| `wf clean <task_id> [--force] [--keep-results]` | 停止服务、删 unit、可选删 worktree                     | 默认只清锁与临时文件                       |
| `wf smoke <spec>`                               | 从 task_spec 派生配置启动 smoke 并做结构验收           | 配置必须从正式 spec 派生                   |
| `wf run <spec> [--force]`                       | 启动 systemd 正式任务                                  | 默认拒绝重复；`--force` 生成新时间戳目录 |
| `wf status <task_id>`                           | 查询 systemd + STATUS.json 双通道                      | 进程消失 ≠ 成功                           |
| `wf sync <task_id>`                             | rsync 拉取到 Mac 归档路径                              | 使用最新时间戳或指定时间戳                 |
| `wf verify <task_id>`                           | 通用验收器                                             | 默认验最新时间戳目录                       |
| `wf git-check`                                  | 变更范围 + 测试 + 交付清单                             | 不自动 commit                              |

**典型成功路径**：

```
doctor → prepare → smoke → run → (轮询 status) → sync → verify → git-check
```

## 6. 关键工程规则（必须遵守）

### 6.1 幂等与锁

- worktree 不存在 → 创建并写锁
- worktree 存在且 spec_hash 一致 → 复用
- worktree 存在但 spec_hash 不一致 → **立即失败**，提示 `wf clean --force`
- `wf run` 默认拒绝已存在同名服务；失败状态需先 clean；仅 `--force` 允许新时间戳目录重跑

### 6.2 路径与时间

- task_spec 内全部使用相对路径（venv 通过 `python.source` 显式声明）
- `wf` 在运行时根据当前机器拼接绝对前缀
- doctor 必须检查 Mac ↔ WSL UTC 时间差（> 5s 报 warning）

### 6.3 失败分类

```
environment  → SSH / 时钟 / 依赖 / Git 状态
transport    → rsync / 文件缺失 / 哈希不一致
structure    → schema / 文件齐全性 / provenance 缺失
numerical    → NaN/Inf / solver 内部失败
scientific   → 科学门控未通过（由专用验收器判定）
```

基础设施失败不得写成 Scientific FAIL。

### 6.4 历史证据保护

- 正式结果始终写入带时间戳的子目录
- `--force` 重跑只生成新目录，禁止覆盖任何已有结果

### 6.5 参数注入防冲突

- `--output` 与 `--workers` 由 wf 统一注入
- 用户 `args` 中若已包含同名参数 → 立即失败

## 7. SSH 基建（拯救者 Windows）

**已落地方案：OpenSSH Match + ForceCommand + PowerShell Shim**

`DefaultShell=wsl.exe` 方案经两次实测均失败（OpenSSH 对非 cmd.exe shell 强制追加 `-c`，wsl.exe 不认）。
正确做法见 `docs/ssh_setup.md`，核心要点：

- 不修改全局 `DefaultShell`，使用 `Match User` + `ForceCommand`
- ForceCommand 调用 PowerShell shim（`wsl_shim.ps1`），通过 `$env:SSH_ORIGINAL_COMMAND` 转发命令
- Shim 内执行：`wsl.exe -u lsy -- /bin/bash -c "$command"`
- 2026-07-27 已部署并验证通过（身份、引号、管道、退出码全部正常）

效果：
- Mac 侧 `ssh legion "命令"` 直接进入 WSL bash，引号只剩一层
- 回滚只需注释 sshd_config 的 Match 块并重启 sshd

## 10. 关键决策记录

| 决策        | 选择                               | 理由                                  |
| ----------- | ---------------------------------- | ------------------------------------- |
| SSH 方式    | Match + ForceCommand               | 消除引号嵌套且不影响其他 Windows 用途 |
| 同步        | rsync --checksum --partial         | CSV/MB 级足够，简单可靠               |
| CLI         | Typer                              | 类型即文档，Agent 友好                |
| 输出        | 统一 JSON + next_action            | 零推理成本推进                        |
| 配置        | YAML task_spec                     | 声明式、可 diff、可版本控制           |
| task_id     | 自动推导`commit_short/task_name` | 避免手写与 commit 不一致              |
| Python 路径 | `source: main_repo \| worktree`   | 正确处理 venv 位于主仓库的情况        |
| output_dir  | 基准路径 + 强制时间戳子目录        | 历史证据永不覆盖                      |
| 参数注入    | wf 强制追加 --output/--workers     | 防冲突，来源清晰                      |
| 产物后缀    | basename + 运行时拼平台后缀        | 跨平台兼容                            |
| 状态判断    | systemd + STATUS.json              | 进程消失 ≠ 成功                      |
| 锁          | .wf_lock + spec_hash               | 防止配置混用                          |
| 测试        | 依赖注入 + MockExecutor            | 可单测、可回归                        |
