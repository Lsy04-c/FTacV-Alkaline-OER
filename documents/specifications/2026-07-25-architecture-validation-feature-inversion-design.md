# OER-FTAcV 底层架构验证与特征反演设计

日期：2026-07-25
周期：一周
目标：验证现有 FTacV 反演链路，判断系统偏差来自实现错误、参数不可识别还是缺失物理项，并用更可靠的实验特征提高参数恢复精度。

## 1. 决策与范围

本周采用“验证优先、最小可证伪扩展”路线。项目先证明现有计算链正确，再讨论新增物理参数。拟合误差下降本身不能证明模型正确。

本周包含：

1. 审计原始数据到反演损失的完整链路。
2. 用合成数据验证正演、特征提取和参数恢复。
3. 计算参数敏感性、相关性和可识别性。
4. 统一完整实验网格与反演网格的残差定义。
5. 在审计通过后，只测试一个高电位缺失物理项。
6. 实现一版基于信噪比的幅值与相位联合特征。
7. 在相同计算预算下比较旧、新两套特征。

本周不包含：

- 同时加入传质、气泡、膜层电阻、LOM和动态重构等多个机制。
- 仅为降低损失而无限放宽参数边界。
- 在特征验证前更换 TPE 优化器。
- 把 H4–H7 全部强制加入四组数据的共同拟合。
- 根据一次较好拟合宣称已证明表面重构或完整 OER 机理。

## 2. 当前事实基线

现有四组 FTacV 数据均可计算 H1–H7，但适合进入当前拟合的通道不同：

| 数据 | 当前拟合通道 |
|---|---|
| `ftacv2-ref-5hz.txt` | H1–H5 |
| `ftacv3-ref-5Hz.txt` | H1–H3 |
| `ftacv4-ref-1hz.txt` | H1–H3 |
| `ftacv8-ref-5Hz.txt` | H1–H4 |

四组数据的共同通道是 H1–H3。当前 2% 相对 RMS 阈值只能表示幅值达到门槛，不能替代噪声底、重复性和相位稳定性判断。

真正固定 `gamma=3e-9 mol/cm²` 后，`G_OH`、`G_O`和`scaling_OOH_OH`跨数据稳定，`k0_1~k0_4`仍不可靠。现有诊断显示完整高电位区存在结构化残差，单独扫描 Ru 或增加高电位损失权重不能稳定消除该残差。

仓库中已有未经完整验证的 `gamma_eff(E)` 初稿。它是候选实验模型，不是已经接受的主模型。

## 3. 系统边界

验证链路按六层拆分：

```text
原始数据
→ 实验元数据与电位/时间轴
→ DC及谐波提取
→ AEM正演
→ 特征对齐与加权
→ 目标函数与参数反演
```

每层提供明确输入、输出和独立测试。下游测试失败时，先定位最早出现偏差的层，不用优化器掩盖上游错误。

### 3.1 数据层

输入为原始 CV/FTacV 文件。输出包含时间、电位、电流、采样率、基频、交流幅值、扫描速率和扫描方向。

验证内容：

- 文件列含义与单位；
- 时间是否单调；
- 电位轴和扫描方向；
- 基频、采样率和每周期采样点；
- 裁剪、排序和插值是否保留信号方向；
- 不同数据文件是否使用相同参考电位定义。

### 3.2 信号层

输入为实验或合成电流。输出为 DC、H1–H7的复数响应、幅值包络、相位和噪声估计。

验证内容：

- FFT频率中心与带宽；
- 边界填充和窗函数影响；
- 时域、频域和电位域对齐；
- 合成正弦信号的幅值与相位恢复；
- 同一信号在不同采样率、长度下的稳定性；
- 峰位不因滤波参数发生不可接受的漂移。

### 3.3 物理层

输入为参数和实验波形。输出为覆盖度、表面电位和总电流。

验证内容：

- 单位和量纲；
- 电荷守恒；
- 五种覆盖度保持在物理范围且总和为1；
- ODE收敛和时间步独立性；
- `A`、`gamma`、`Cdl`、`Ru`的使用位置一致；
- 参数单调性符合物理预期；
- 关闭候选扩展时严格恢复基线 AEM。

### 3.4 特征层

旧特征保留为基线。新特征由以下部分组成：

- DC形状和幅值；
- H1–H3共同通道的幅值、相位、峰位、峰宽和峰面积；
- 数据特有的 H4/H5仅作为附加证据；
- 每通道噪声底和SNR；
- 有重复数据时加入重复性权重。

新特征保留跨谐波真实幅值比例。每通道归一化只用于数值尺度控制，不能消除物理幅值信息。

### 3.5 目标函数层

目标函数采用可追踪分量：

```text
loss_total
= loss_dc
+ loss_common_harmonics
+ loss_dataset_specific_harmonics
+ loss_phase
+ loss_physical
```

每项单独输出，避免总损失掩盖某个通道恶化。通道权重来自SNR和重复性；缺少重复实验时，报告该权重只基于噪声估计。

### 3.6 反演层

本周保持 TPE 作为默认优化器，固定相同试验次数、随机种子集合和运行预算。旧、新特征使用相同预算比较。

反演结果必须包含：

- 最优参数；
- 每个损失分量；
- 参数是否触及边界；
- 多随机种子离散度；
- 合成参数恢复误差；
- 跨数据参数CV；
- 正演次数和运行时间。

## 4. 参数审计与缺项判别

参数按四类标记：

| 类型 | 含义 | 处理 |
|---|---|---|
| measured | 可由实验独立测量 | 固定或窄先验 |
| literature | 有文献范围 | 使用有来源的边界 |
| identifiable | 当前数据能提供独立信息 | 允许反演 |
| coupled/unresolved | 与其他参数补偿或不敏感 | 固定、合并或只报告范围 |

参数审计使用局部敏感性、成对相关性和合成恢复结果。新增参数必须满足：

1. 对至少一个可信特征产生独立响应。
2. 不与现有参数近乎完全共线。
3. 在合成数据中可恢复，或明确只能得到范围。
4. 在真实数据多随机种子反演中不总是触及边界。
5. 改善结构化残差，而非只降低单个归一化分数。

若参数不满足这些条件，项目不把它作为自由反演参数。

## 5. 最小缺失物理项实验

审计通过后，第一候选项为高电位有效活性位增长：

```text
gamma_eff(E)
= gamma0 × [1 + beta_recon × sigmoid((E - E_recon) / w_recon)]
```

该表达式只用于检验“高电位活性位增加能否解释结构化残差”。基线模型设置 `beta_recon=0`。

实验采用嵌套对照：

- M0：固定 `gamma` 的基线 AEM；
- M1：仅增加 `beta_recon`，固定 `E_recon`和`w_recon`；
- M2：仅当 M1通过验收时，允许一个额外重构参数变化。

模型比较同时检查：

- 高电位 DC 残差；
- H1–H3幅值和相位；
- 参数边界命中；
- 热力学参数跨数据稳定性；
- AIC/BIC或等价的复杂度惩罚指标；
- 关闭扩展后是否恢复 M0。

若 M1不能在多数数据上产生一致改善，本周停止该方向，不继续增加重构参数。

## 6. 一周执行顺序

### 第1天：版本基线与数据契约

- 审计当前未提交修改，区分历史变更、实验输出和候选模型。
- 保存基线测试、参数和四组数据诊断。
- 建立数据层契约和残差符号测试。

输出：基线报告、变更归属清单、数据契约测试。

### 第2天：信号与正演验证

- 用已知幅值和相位的合成信号验证 H1–H7提取。
- 测试采样率、数据长度和滤波带宽敏感性。
- 检查覆盖度、电荷守恒和ODE步长收敛。

输出：信号恢复报告、物理不变量测试。

### 第3天：参数可识别性

- 运行参数敏感性和相关性分析。
- 执行合成数据恢复。
- 形成固定、合并、自由和仅报告范围的参数清单。

输出：参数审计报告和机器可读结果。

### 第4天：残差审计与缺项决策

- 统一完整实验网格和反演网格。
- 分别报告低、中、高电位残差及H1–H3残差。
- 判断当前证据是否允许测试 `gamma_eff(E)`。

输出：残差口径报告和模型实验准入结论。

### 第5天：最小物理项对照

- 比较 M0和M1。
- 只有 M1通过准入标准时才运行 M2。
- 记录拟合改善、参数稳定性和复杂度代价。

输出：模型比较报告和图。

### 第6天：新特征实现与比较

- 加入复数谐波、相位和SNR权重。
- 在相同预算下比较旧、新特征的合成恢复和真实数据表现。

输出：特征比较报告和参数恢复表。

### 第7天：综合结论与下一版决策

- 汇总通过和失败的假设。
- 更新项目状态、结论边界和后续优先级。
- 形成可展示图表。

输出：周总结和下一版本建议。

## 7. 验收标准

### 7.1 架构验证通过

- 合成谐波的幅值和相位误差有明确容差且测试通过。
- 完整网格与反演网格使用同一残差符号。
- 物理覆盖度和电荷守恒测试通过。
- ODE结果在更小时间步下保持稳定。
- 合成数据能恢复至少一组设计为可识别的参数。

### 7.2 新特征通过

与旧特征相比，新特征在相同预算下满足以下多数条件：

- 合成参数恢复误差下降；
- 多随机种子离散度下降；
- H1–H3的实验残差下降；
- 热力学参数跨数据CV不恶化；
- 参数边界命中不增加；
- 运行成本增幅可解释。

### 7.3 候选物理项通过

M1必须满足：

- 至少3/4数据的高电位结构化残差改善；
- H1–H3总体不恶化；
- `G_OH`、`G_O`和`scaling_OOH_OH`稳定性不显著下降；
- `beta_recon`不在所有数据中触及同一边界；
- 复杂度惩罚后的模型比较支持M1。

通过只表示该项值得进一步实验验证，不表示已证明表面重构。

## 8. 失败处理

- 数据层失败：停止反演比较，先修正输入和坐标契约。
- 信号层失败：停止解释谐波差异，先修正滤波和相位恢复。
- 物理层失败：停止新增参数，先修正方程、单位或数值实现。
- 合成恢复失败：将相关参数标记为不可识别，不用真实数据强行解释。
- M1失败：回退到 M0，记录否定结果，不继续增加重构自由度。
- 新特征失败：保留旧特征基线，分析失败来自噪声、相位不稳还是权重设计。

任何失败都必须保存复现命令、输入、软件版本和结果文件。

## 9. 版本、文档与GitHub规则

每个版本只回答一个可验证问题。完成顺序固定为：

1. 写测试和验收条件。
2. 实现最小变更。
3. 运行相关测试和回归测试。
4. 生成报告与图表。
5. 更新 `WORK_STATUS.md`及该版本专题文档。
6. 审查差异，排除无关文件。
7. 提交并推送 GitHub。

验证失败的实验可以保存为诊断提交，但提交信息和项目文档必须明确标记失败结论；不得作为完成版本发布。

## 10. 协同边界

Codex负责架构决策、任务拆分、最终代码审查、验证和Git提交。Claude Code/DeepSeek V4可承担边界清楚、容易复核的任务，例如静态扫描、测试缺口清单、独立结果复算和文档初审。

协作者不得：

- 自行修改 Codex 或 DeepSeek 的全局配置；
- 未经复核直接决定模型结论；
- 把未验证结果写成已确认事实；
- 混合提交无关工作区修改。

所有协作结果进入主线前由 Codex依据代码、测试和项目数据复核。

## 11. 本周最终交付

本周结束时，项目应提供：

1. 可复现的底层链路验证报告。
2. 参数可识别性与缺失参数审计。

- 已由测试确认的实现事实；
- 由数据支持的模型判断；
- 尚需独立实验验证的物理假设。
